# n8n: учебный прототип анализа событий информационной безопасности

## Цель

Создать и исследовать визуальный процесс, который анализирует искусственные записи об аутентификации и выделяет события, удовлетворяющие правилу: **не менее 5 неуспешных попыток входа за 15 минут И подключение из внешней сети**.

В сценарии **нет искусственного интеллекта**. Это первая ступень освоения автоматизации и ветвления. Используются синтетические данные и учебный критерий; обнаружение по нему не доказывает факт атаки, а отсутствие срабатывания не означает отсутствие угрозы.

## Состав комплекта

- `compose.yml` — параметры локального запуска n8n в Docker;
- `n8n_ib_first_workflow.json` — сценарий для импорта в n8n;
- `test_events.json` — копия 12 искусственных событий, использованных в сценарии (справочные данные).

## Установка и запуск в Windows

1. Установите Docker Desktop с официального сайта: https://www.docker.com/products/docker-desktop/. На Windows должна работать поддержка WSL 2, если Docker её запросит. Запустите Docker Desktop.
2. Создайте на компьютере папку `C:\n8n-ib`. Перенесите в неё файл `compose.yml`.
3. Откройте **PowerShell** в этой папке: в адресной строке проводника введите `powershell` и нажмите Enter.
4. Выполните команду:

   ```powershell
   docker compose up -d
   ```

   При первом запуске Docker загрузит образ n8n из Интернета.
5. Откройте в браузере: http://localhost:5678. При первом входе создайте локальную учётную запись администратора.
6. В n8n откройте редактор нового рабочего процесса, выберите меню `...` → **Import from File** и укажите `n8n_ib_first_workflow.json`.
7. Нажмите **Execute workflow** (или эквивалентную кнопку ручного запуска в установленной версии). Изучите выходные данные узла «Учебные события (12)», затем ветви **true** и **false** узла «Выявить подозрительные входы».

## Проверка результата

- Всего записей: **12**.
- Ветвь `true`: **5** записей (`E001`, `E003`, `E006`, `E008`, `E011`).
- Ветвь `false`: **7** записей.
- В каждой выходной записи появляется поле `status`; исходные поля сохраняются.

## Самостоятельная проверка

1. Измените порог числа неудачных входов с 5 на 8. Повторите запуск. Должно остаться **2** события (`E008`, `E011`).
2. Верните порог 5. Замените `AND` на `OR` между условиями. Должно стать **10** событий в ветви `true` (единственные исключения — `E002`, `E012`).
3. Верните исходное условие `AND` и порог 5.
4. Откройте узел «Учебные события (12)» и найдите массив `events`. Дополните его одним искусственным событием и предскажите результат до запуска.

## Значение полей

`event_id` — учебный идентификатор; `event_time` — условное время события; `account` — тестовая учётная запись; `failed_attempts` — число неудачных попыток за 15 минут; `network` — внешняя/внутренняя сеть; `source_ip` — тестовый IP-адрес.

Публичные IP-адреса взяты из диапазонов документации: `192.0.2.0/24`, `198.51.100.0/24`, `203.0.113.0/24`. Это не реальные адреса атакующих.

## Управление локальным экземпляром

```powershell
docker compose ps       # проверить состояние
docker compose logs -f  # посмотреть сообщения приложения; Ctrl+C — выйти из просмотра
docker compose stop     # остановить (данные сохраняются)
docker compose start    # повторно запустить
docker compose down     # удалить контейнер, сохранив том данных
docker compose up -d    # запустить после остановки/удаления
```

**Не выполняйте** `docker compose down -v`, если хотите сохранить учебные сценарии: этот вариант удаляет также том с данными. Порт привязан к `127.0.0.1`, поэтому n8n не открыт для подключения с других компьютеров.

## Примечание о тестировании

Файлы сценария и конфигурации прошли структурную проверку, а ожидаемые числа рассчитаны на наборе данных. Реальное выполнение в Docker/n8n на вашем компьютере здесь не проводилось. Интерфейс конкретной версии может незначительно отличаться.
